# 三人掼蛋

一家人一起玩的三人掼蛋网页游戏。不用装App、不用注册。

- **在一起的时候**：一台电脑开着服务，其他人连同一个WiFi，手机浏览器打开就行（下面「怎么开始」）。
- **不在一起的时候**：部署到云上，各自在家用手机打开同一个网址（下面「部署到公网」）。

## 怎么开始

1. 找一台电脑当"主机"，装好 [Node.js](https://nodejs.org/)（v18 以上）。
2. 在项目目录里执行：

   ```bash
   npm install
   npm start
   ```

3. 终端会打印出局域网地址，例如：

   ```
   ========================================
     三人掼蛋已启动！
     家人连同一个WiFi，用浏览器打开：
       http://192.168.1.5:3000
   ========================================
   ```

4. 三个人都连**同一个WiFi**，用手机或电脑浏览器打开这个地址。
   （不在一起？看下面「部署到公网」。）
5. 各自输入名字 → 一个人点「创建房间」，把 4 位房间号告诉另外两人 → 另外两人输房间号加入（也可以直接点大厅里的房间）。
6. 三人到齐后，房主点「开始游戏」。

打不开的话检查三点：是不是同一个WiFi（别一个连WiFi一个用流量）、地址有没有输错、电脑防火墙是否拦了 3000 端口。

## 玩法

默认用**两副牌共 108 张**，三人各发 36 张，先出完手牌的是「头游」。

### 用几副牌

房主在开局前可以选 1 / 2 / 3 副牌（三种都能被 3 整除，正好平分）：

| 副数 | 总张数 | 每人 | 每个点数几张 | 王炸 | 特点 |
|------|--------|------|--------------|------|------|
| 1 副 | 54 | 18 | 4 | 大王+小王 | 一局快，炸弹少 |
| **2 副（默认）** | **108** | **36** | **8** | 四王炸 | 掼蛋标准 |
| 3 副 | 162 | 54 | 12 | 六王炸 | 牌多，炸弹满天飞 |

两副牌每个点数有 8 张，所以**摸到 5 张甚至更多同点数是正常的**——那就是 5 张炸弹。
实测约 98% 的手牌里至少有一个 4 张炸，约 66% 至少有一个 5 张炸。炸弹张数越多越大。

### 牌型

| 牌型 | 说明 |
|------|------|
| 单张 | 一张牌 |
| 对子 | 两张同点数 |
| 三张 | 三张同点数 |
| 三带一 / 三带二 | 三张 + 1张 / 三张 + 一对 |
| 顺子 | 5张及以上连续单张（3~A之间，不含2和王）|
| 连对 | 3对及以上连续对子，如 556677 |
| 炸弹 | 4 张及以上同点数，张数越多越大 |
| 同花顺 | 同花色的5张顺子 |
| 王炸 | 场上全部的王（2 副牌就是四王炸），最大 |

### 大小顺序

- 普通牌：`3 < 4 < … < K < A < 2 < 级牌 < 小王 < 大王`
- **级牌**：当前这局打几，几就是级牌。比如打 7，那么所有的 7 都比 A 和 2 大（顺子里的 7 仍按普通的 7 算）。
- **万能牌**：当前级牌的**红桃**（比如打 7 时的 ♥7）可以当任意牌用，凑对子、三张、顺子、炸弹都行。界面上会用金色标出来。
- **炸弹强弱**：`4张 < 5张 < 同花顺 < 6张 < 7张 < 8张 < 四王炸`。炸弹可以压任何普通牌型。

### 出牌规则

- 轮到你时，要么出比上家大的同类型同张数的牌，要么用炸弹压，要么点「不要」。
- 一圈都不要之后，重新开一轮，可以随便出。
- 先出完的是头游。头游走后**接风**：牌桌清空，由他的下家直接领出新一轮，
  剩下两人继续打完二游、末游（不用再去压一个已经离场的人的牌）。
- 每局结束后级牌升 1 级（头游赢一局升一级），从 2 一路打到 A；打到 A 再赢一局就是整场胜利，然后从 2 重新开始。

### 界面上的帮手

- **提示**：自动帮你选出一手能压过上家的牌。
- 选牌时下方会实时显示"**三带二 — 可以出**"或"**压不过上家**"，不用担心出错牌被拒。
- **理牌**：可切换「按大小排」和「把对子/三张排到一起」。
- 金色边框的是万能牌，淡蓝底的是级牌。

### 轮到你时的提醒

一家人各看各的手机，很容易错过自己的回合，所以做了四重提醒：

1. 顶部横幅变成会呼吸的**金色「👉 轮到你了」**
2. **提示音**（上行两声）
3. **手机震动**
4. 屏幕四周泛起**一圈金光**，自己的手牌区也亮起来

如果切到了别的App或别的标签页，**浏览器标签标题会闪烁「🔔 轮到你出牌了！」**。

### 掉线了怎么办

手机切到别的App、锁屏、WiFi 抖一下，浏览器都会掐断连接——这是手机浏览器的正常行为，躲不掉。所以做了这些：

- **掉线不会让整局作废**。座位和手牌都给你留着，其他人继续等你，牌桌上会显示「XX 掉线了，等他重连…」。
- **回来自动接上**。切回页面的一瞬间就重连，不用做任何操作，手牌原封不动。
- **刷新页面也能回去**。浏览器崩了、手机把网页清掉了，重新打开地址就直接回到牌桌，连名字都不用重输。
- **服务器重启也能自动连回来**（会一直重试，最多5秒一次）。
- 留的时间是 **3 分钟**，超过才真的当你退出。想立刻离开就点「退出」。

顺带说一句：服务器每 15 秒探一次活。有些情况下连接是"悄悄死掉"的（手机休眠、WiFi 断了却没发断开信号），靠这个心跳才能及时发现，否则其他人会一直干等。

### 音效与动画

- 出牌、过牌、发牌、选牌、炸弹、结算都有音效，全部是用 Web Audio **实时合成**的，
  不加载任何音频文件，所以离线、局域网下都能正常出声，也不增加加载时间。
- 出牌时牌会**从下方飞到牌桌上**；发牌时手牌**逐张滑入**；
  有人放**炸弹时整个画面会抖一下**。
- 右上角 🔊 可以**随时静音**（会记住你的选择）。
- 系统里开了"减少动态效果"的话，动画会自动关闭。

## 部署到公网（异地一起玩）

局域网玩法不用部署。想异地一起玩，把它放到云上就行——这是个普通的 Node
服务，任何支持 **WebSocket 长连接**的平台都能跑（静态托管和纯 Serverless
不行，它们不支持长连接）。

仓库里已经准备好了配置文件，选一个平台即可：

### 方案一：Render（最省事，不用装东西，不用信用卡）

1. 代码推到 GitHub（已经在了）。
2. 打开 [render.com](https://render.com) 注册，选 **New → Blueprint**，
   连上这个仓库。它会自动读取仓库里的 `render.yaml`。
3. **手动设置密码**：进服务页面 → 左侧 **Environment** → **Add Environment
   Variable**，填 `GAME_PASSWORD` = 你们的家庭密码，保存后会自动重新部署。

   > `render.yaml` 里这个变量标了 `sync: false`（值不从仓库同步，避免密码
   > 进版本库）。Render 只在**首次创建**服务时才弹窗让你填；如果是把
   > Blueprint 关联到已有服务，它不会问，必须自己去后台加。

4. 拿到 `https://xxx.onrender.com` 网址。**发给家人之前**先打开
   `https://xxx.onrender.com/config` 确认返回 `{"passwordRequired":true}`，
   否则网站是完全敞开的，谁都能进。

注意：免费套餐在**一段时间没人访问后会休眠**，下次打开要等几十秒冷启动。
打牌过程中连接是活的，不会中途休眠。具体额度和条款以 Render 当前页面为准。

### 方案二：Fly.io（不休眠，响应更快，需要绑卡）

```bash
brew install flyctl          # macOS
fly auth signup              # 或 fly auth login
fly launch --no-deploy       # 会读仓库里的 fly.toml
fly secrets set GAME_PASSWORD=你们的密码
fly deploy
```

`fly.toml` 里已经把机器设成**不自动停机**（`auto_stop_machines = false`），
免得打到一半被停掉。区域默认香港（`hkg`），可以改成 `nrt`(东京)、
`sin`(新加坡)、`sjc`(美西) 等离你们更近的。

### 方案三：自己的服务器 / 群晖 / 树莓派

仓库里有 `Dockerfile`：

```bash
docker build -t guandan .
docker run -d --restart unless-stopped -p 3000:3000 \
  -e GAME_PASSWORD=你们的密码 guandan
```

再用 Nginx / Caddy 配个域名和 HTTPS 就行（**记得给 WebSocket 放行
`Upgrade` 和 `Connection` 头**，否则连不上）。

### 关于密码

一旦放到公网，**谁都能打开这个网址、在大厅里看到并加入你们的房间**。
所以设了 `GAME_PASSWORD` 环境变量：设了就必须输对密码才能进，
密码会记在浏览器里，不用每次输。

局域网自己玩不设这个变量就行，行为和以前完全一样。

### 部署后要知道的

- **必须是 HTTPS**。前端会自动用 `wss://`，云平台一般默认就给 HTTPS。
- **房间状态存在内存里**，服务重启/重新部署会清空，大家回到大厅重进即可。
  正在打的一局会丢（家用场景够了，没必要上数据库）。
- **每 15 秒一次心跳**，顺便能穿过一些云平台对空闲连接的超时回收。
- 异地打牌延迟高一点很正常，出牌是服务器裁决的，不会因为延迟出错。

## 开发

```bash
npm test           # 跑全部测试
npm run test:rules # 只测牌型和比牌规则（105项）
npm run test:flow  # 只测完整对局流程（走真实WebSocket，27项）
```

`cardLogic.js` 是纯规则逻辑（牌型判定、比大小、提示搜索），服务器和浏览器共用同一份，保证前后端判定完全一致。

关于万能牌的一个实现要点：因为万能牌能当任意牌，同一手牌往往有**多种读法**
（比如 4-5-6-7-万 既能当 3~7 也能当 4~8）。所以 `detectCombos()` 会列出所有
合法读法，`detectCombo()` 取其中最有利的一种，`findBeatingCombo()` 则找一种
压得过上家的。只取第一个读法会把牌读小，导致明明压得过却被判"压不过"。
